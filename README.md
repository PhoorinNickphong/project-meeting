# แอปจดประชุม

แอปเดสก์ท็อปสำหรับจดประชุมภาษาไทยบน Windows บันทึกเสียง ระบุผู้พูดด้วยปุ่มลัด และถอดเสียงบนเครื่องด้วย Rust และ OpenThai

## สถานะโครงการ

กำลังพัฒนาเฟส 1 คอนโซลสีอำพันบันทึก WAV จากไมค์ ติดชื่อผู้พูดได้สูงสุด 5 คน ปักช่วงสำคัญ และเปิดฟังย้อนหลัง โค้ด Alpha 2 เพิ่มการถอด WAV ภาษาไทยหลังประชุมด้วย OpenThai ONNX FP32 บน Windows x64

## ลองบน Windows

สำหรับผู้ทดสอบ ดาวน์โหลด ZIP ตัวแอป Windows x64 จาก [GitHub Releases](https://github.com/PhoorinNickphong/project-meeting/releases) แตกไฟล์ทั้งหมดแล้วเปิด `meeting-notes.exe` ใช้อัดและฟังย้อนหลังได้ทันที เมื่อต้องการถอดเสียง ให้เตรียมโมเดล OpenThai แยกหนึ่งครั้งตาม [คู่มือภาษาไทย](docs/windows-alpha-2.txt) แอปจะค้นหาจากโฟลเดอร์ข้าง `.exe` อัตโนมัติ

รัน `cargo run --locked --bin meeting-notes` จากโฟลเดอร์โปรเจกต์ แอปจะเปิดหน้าต่าง Microsoft Edge และเชื่อมกับโปรแกรม Rust ผ่าน loopback ในเครื่อง ใช้งานได้โดยไม่ใช้บัญชีหรือบริการคลาวด์

1. เลือก **ประชุมใหม่** กรอกชื่อการประชุมและผู้พูด จากนั้นทดสอบไมค์
2. กด **เริ่มบันทึก** แล้วใช้ `1–5` หรือคลิกชื่อเพื่อสลับผู้พูด กด `M` เพื่อปักช่วงสำคัญ
3. กด **หยุดบันทึก** แล้วคลิกเวลาที่ปักหรือเวลาที่สลับผู้พูดเพื่อเลื่อนเสียงไปยังตำแหน่งนั้น
4. ในหน้าฟังย้อนหลัง กด **ถอดเสียงภาษาไทย** เมื่อเตรียมโมเดลแล้ว หรือดาวน์โหลด WAV และส่งออกจุดเวลาเป็น JSON

ไฟล์อยู่ใต้ `%LOCALAPPDATA%\Meeting Notes\meetings` ตามค่าเริ่มต้น หากปิดหน้าต่างระหว่างอัดและโปรแกรม Rust ยังทำงานอยู่ ให้รอประมาณ 30 วินาทีหลังหยุดรับข้อมูลจากหน้าต่างเดิม แล้วกด **รีเฟรช → ตรวจไฟล์ที่ค้าง** เพื่อเปิดเสียงส่วนที่ลงดิสก์แล้ว หากปิดโปรแกรมทั้งตัว ให้เปิดแอปขึ้นใหม่เพื่อกู้ได้ทันที เมื่อใช้งานเสร็จ ปิดโปรแกรมได้จาก **ตั้งค่า → ออกจากแอป**

ถ้าไมค์หลุด พื้นที่เต็ม หรือบันทึกลงดิสก์ตามเสียงไม่ทัน หน้ากู้ไฟล์และหน้าฟังย้อนหลังจะแสดงสาเหตุและเวลาถึงช่วงที่เก็บเสียงได้ ถ้าพื้นที่เต็ม ให้เพิ่มพื้นที่ว่างก่อนกู้ไฟล์

## เตรียม OpenThai สำหรับ `v0.1.0-alpha.2` บน Windows x64

เตรียมไฟล์ครั้งเดียวบนเครื่องที่ดาวน์โหลดได้ จากนั้นย้ายโฟลเดอร์โมเดลและ DLL ไปเครื่องออฟไลน์ได้ ใช้ CPU และไม่ต้องติดตั้ง Python หรือใช้ API Key

1. ดาวน์โหลด `openthai2.0-asr-streaming-fp32.asr.zip` และ `encoder.onnx.data` จากหน้าไฟล์ของ iApp แตก ZIP แล้ววาง `encoder.onnx.data` ข้าง `encoder.onnx`, `decoder_joint.onnx` และ `tokens.txt` ทั้งหมดใช้พื้นที่ประมาณ 2.6 GB หลังแตกไฟล์ [ไฟล์โมเดล FP32 ที่ทดสอบ](https://huggingface.co/iapp/OpenThai2.0-ASR-Streaming-ONNX/tree/9f142a43e4d35a422c1c7dac40772ef707387ebc)
2. ZIP ตัวแอปมี `onnxruntime.dll` อยู่แล้ว สำหรับการ build จากซอร์ส ดาวน์โหลดแพ็กเกจ `Microsoft.ML.OnnxRuntime` รุ่น `1.24.4` จาก NuGet เปิด `.nupkg` เป็น ZIP แล้วนำ `runtimes/win-x64/native/onnxruntime.dll` มาวางข้าง `meeting-notes.exe` [แพ็กเกจ ONNX Runtime CPU 1.24.4](https://www.nuget.org/packages/Microsoft.ML.OnnxRuntime/1.24.4)
3. หาก build จากซอร์ส ให้รัน `cargo build --locked --release --bin meeting-notes` แล้ววาง DLL ใน `target/release` สำหรับ `cargo run` แบบ debug ใช้ `target/debug` วางโฟลเดอร์ `models/OpenThai2.0-ASR-Streaming-ONNX` ข้าง `.exe` หรือในโฟลเดอร์โปรเจกต์สำหรับ build ของ Cargo ถ้าเก็บโมเดลที่อื่น ให้กำหนดพาธที่ **ตั้งค่า → ถอดเสียงออฟไลน์ → บันทึกพาธ**
4. หยุดบันทึกหรือเปิดการประชุมเดิมจากประวัติ แล้วกด **ถอดเสียงภาษาไทย** คลิกเวลาในผลถอดเพื่อเลื่อนไปยังช่วงนั้น ผลบันทึกใน `transcript.json` ข้าง `audio.wav` และเปิดดูได้เมื่อกลับมาที่การประชุมเดิม

แอปแบ่ง WAV ที่จุดกดสลับผู้พูดและช่วงพักเสียง เวลาบนหน้าจอคือจุดเริ่มของช่วงเสียง ช่วงที่ยังไม่ได้กดชื่อจะแสดง **ไม่ทราบผู้พูด** หากกดชื่อช้าหรือมีเสียงพูดซ้อน การผูกชื่อจะสะท้อนจุดที่กดไว้ เครื่องใช้หน่วยความจำหลาย GB ขณะโหลด FP32 และรับถอดไฟล์ทีละการประชุม [รายละเอียดโมเดลและข้อจำกัด](https://huggingface.co/iapp/OpenThai2.0-ASR-Streaming-ONNX)

ไฟล์โมเดลใช้สิทธิ์ OpenMDW-1.1 เก็บไฟล์ `LICENSE` ของโมเดลไว้ด้วยถ้าจะนำไฟล์โมเดลไปแจก [สัญญาอนุญาตของ OpenThai](https://huggingface.co/iapp/OpenThai2.0-ASR-Streaming-ONNX/blob/main/LICENSE)
